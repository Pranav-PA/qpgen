# QPGen — AI Question Paper Generator for Teachers

A public multi-user web app that generates chapter-scoped JEE/NEET/Board question
papers with full answer keys. Teachers review and edit every question, then export
a print-ready PDF (with institution letterhead) and editable Word documents — the
question paper and answer key always as **separate** files.

## How it works

- **Chapter scoping + verification**: every batch of questions is generated by one
  model call and then independently re-solved by a second verifier call that checks
  the answer, chapter scope, and option validity. Failures get a visible
  "⚠ Needs review" flag — nothing is silently wrong.
- **Batched generation**: papers generate in batches of 6 questions so serverless
  time limits are never hit; a partial failure is resumable from the paper page.
- **Board blueprints**: for Board/Custom papers you can upload your board's
  blueprint image or PDF. A vision call reads the parts and the chapter-by-part
  grid; the paper then prints in the official pattern (PART-A/B/C/D with their
  own instruction lines, optional sub-groups such as "I. Pick the correct
  option" / "II. Fill in the blanks", and continuous numbering).
- **Real math everywhere**: questions are stored with inline LaTeX and rendered
  by KaTeX, with the fonts embedded directly into the exported PDF.
- **Switchable AI backend**: Google Gemini by default (`gemini-3.6-flash` to
  write, `gemini-3.5-flash-lite` to verify) with OpenAI as an alternative you
  can select from the admin panel.
- **Reference PDFs are never stored**: pages are rendered to images in the browser
  (PDF.js), summarized into a style profile by one vision call, and discarded.
- **Abuse protection**: per-user daily caps, a global daily cap, an admin kill
  switch, optional Turnstile captcha, and email confirmation — all enforced
  server-side with an atomic SQL function.

## Stack

Next.js (App Router) on Vercel · Supabase (Auth, Postgres with RLS, Storage for
logos) · OpenAI API (GPT-5.6 family by default, configurable) · KaTeX / temml /
mathml2omml · `docx` for Word export · print stylesheet for PDF.

## Setup

### 1. Supabase

1. Create a project at [supabase.com](https://supabase.com).
2. In the SQL editor, run `supabase/migrations/001_init.sql` (creates tables,
   RLS policies, the rate-limit function, the signup trigger, and the `logos`
   storage bucket).
3. **Auth → Providers**: enable Email (leave "Confirm email" ON) and Google
   (paste OAuth client credentials from Google Cloud Console; set the redirect
   URL Supabase shows you).
4. **Auth → URL configuration**: set your site URL and add
   `https://<your-domain>/auth/callback` to the redirect allow-list.
5. Optional but recommended for a public deploy — **Auth → Attack protection**:
   enable captcha with Cloudflare Turnstile and put the site/secret keys in the
   env vars below.

### 2. Environment variables

Copy `.env.example` to `.env.local` and fill in:

| Variable | Where to find it |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase → Settings → API |
| `SUPABASE_SERVICE_ROLE_KEY` | same page — **server-only, never expose** |
| `GOOGLE_API_KEY` | aistudio.google.com — the default provider |
| `OPENAI_API_KEY` | platform.openai.com — optional alternative |
| `AI_PROVIDER` | optional; `google` (default) or `openai`, overridden by the admin panel |
| `GEMINI_GENERATION_MODEL` / `GEMINI_VERIFIER_MODEL` | optional; defaults `gemini-3.6-flash` / `gemini-3.5-flash-lite` |
| `OPENAI_GENERATION_MODEL` / `OPENAI_VERIFIER_MODEL` | optional; defaults `gpt-5.6-terra` / `gpt-5.6-luna` |
| `NEXT_PUBLIC_TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | optional captcha |
| `MOCK_AI=true` | optional: run the full flow with free mock questions (no OpenAI key needed) |

### 3. Run locally

```bash
npm install
npm run dev
```

### 4. Make yourself admin

After signing up once, run in the Supabase SQL editor:

```sql
update public.profiles set role = 'admin' where email = 'you@example.com';
```

`/admin` then shows usage stats, real API cost, reported questions, user
management (disable / per-user caps), global limits, and failure logs.

### 5. Deploy to Vercel

Import the repo at vercel.com, add the same env vars (without `MOCK_AI`), deploy.
Then update the Supabase Auth site URL / redirect list to the production domain.

## Costs and limits

- One paper = one unit against the per-user daily cap (default 10, admin-adjustable
  per user). The global daily batch cap (default 500) is the hard budget backstop;
  the admin kill switch pauses all generation instantly.
- Every model call's token usage and dollar cost is logged to `usage_logs`; the
  admin panel shows real 30-day spend.
- Reference PDFs are capped at 10 pages / 20 MB; papers are capped at 50 questions.
- Model pricing for cost logging lives in `src/lib/constants.ts`
  (`MODEL_PRICING`) — update it if OpenAI's pricing changes.

## Safety model

The AI assists; the teacher decides. Every screen that shows generated content
carries a "review before distributing" notice, the verifier flags anything it
cannot confirm, and the answer key is generated alongside every paper so the
teacher can check each question before printing.
