# QPGen bug audit — 8 August 2026

## About this audit

You asked for the BMAD method to "run all the tests". Two things to be clear
about before the findings:

- **BMAD-METHOD is not a test runner.** It is a workflow methodology — agent
  personas and a Clarify → Plan → Build & Verify → Learn loop. Its testing
  piece is a separate "Test Architect" add-on. There is no command in it that
  executes a suite or finds defects.
- **QPGen has no tests to run.** `package.json` defines only `dev`, `build`,
  `start`, `lint`. No test framework is installed, and there is not one
  `.test.*` or `.spec.*` file in `src/`. That is itself finding **M4**.

So this is a risk-first manual audit in the Test Architect spirit: read the
highest-risk paths, verify each suspicion against the code and (where
possible) the live deployment, and record only what is confirmed.

**Scope covered:** generation and batching, reference-led mode, the figure
pipeline, PDF export, rate limiting, RLS, the review screen, the wizard, and
the marketing page. **Not covered:** admin panel internals, auth flows beyond
reading them, anything needing a signed-in browser session (the Browser pane
was not authenticated — see "Not yet verified").

Severity is about what reaches a student or loses a teacher's work, not about
how hard it is to fix.

## Critical

### C1 — "Generate remaining" duplicates questions on a reference paper

**Where:** `src/lib/ai/plan.ts` — `unfilledSlots()`

```ts
if (!plan.some((s) => s.section_id)) return plan.slice(existing.length);
```

Position-aware slot matching was added to fix delete-then-continue, but it only
engages for **blueprint** papers (those are the ones with `section_id`). A
reference-led paper is `mode: "simple"`, so every slot has no `section_id` and
the function falls back to counting.

That fallback is sound for a syllabus paper, where all slots are
interchangeable. It is wrong for a reference paper, where **every slot is a
different source question**. Delete question 3 of 45 and press "Generate
remaining 1": `existing.length` is 44, so the plan resumes at index 44 — the
45th source, which is already on the paper. The teacher gets a duplicate of a
question they already have, and the source they actually vacated is never used.

**Fix direction:** match reference slots by `reference_item_id` (already stored
on each question) rather than by count.

### C3 — The verifier fails every figure question, with a reason that is false

**Where:** `src/lib/ai/prompts.ts` — `verifierSystemPrompt()`, rule 5
**Verified live** on paper `a5954a03` (45 questions, 15 with figures).

Every one of the 15 figure questions is flagged. No text-only question is.
Three of four sampled reasons are the same spurious failure:

> "The question is marked **has_figure: true** but refers to 'the circuits
> shown below' which are entirely absent from the text. It fails the
> self-containment check."

> "…marked has_figure: true but relies entirely on external graphs labeled
> (a), (b), (c), (d) which are missing from the text."

> "…marked has_figure: true and references 'the points A and B, as shown in
> the figure', violating the self-containment rule."

The verifier states the figure flag is set and then fails the question *for
referencing the figure*. Rule 5 already says the opposite — a question marked
`has_figure: true` "may reference the circuit/diagram/graph shown" — so the
model is reasoning past it: it cannot see the diagram, so it treats "absent
from the text I was given" as absent from the paper.

Two harms, and the second is worse than the first:

1. The teacher is told a good question is broken and its diagram missing. The
   natural response is to delete or regenerate a question that was fine.
2. It destroys the signal. With 15 of 15 figure questions failed for a bogus
   reason, a genuine defect in one of them is invisible. This is the check the
   whole "correctness is priority #1" claim rests on.

Note the pipeline's own note on these questions is correct — Q6 carries only
the honest "redrawn … compare it against the original" disclaimer. It is the
model's verdict that is wrong.

**Fix direction:** rule 5 must forbid judging self-containment at all when
`has_figure` is true, not merely permit the reference — e.g. "You cannot see
the figure. Do not comment on whether it exists, and never fail a question for
referring to it. Judge only the physics and the answer." Figures still force
`needs_review` by design, so nothing is lost by removing the verdict.

### C2 — AI-editing a reference question can contradict its printed figure

**Where:** `src/lib/ai/prompts.ts` — `editQuestionSystemPrompt()`

Generation was just fixed so a question carrying a source figure is reproduced
rather than varied — because the figure is the teacher's original and pins
every value in it. The **edit** path has no such rule. A teacher who says
"change the resistor values" gets exactly that, with the original figure still
printed beside it.

This is the same defect class that produced the live paper asking about a
"Red, Red, Orange, Silver" resistor above a figure banded
Yellow-Violet-Brown-Gold. Nothing downstream can catch it: the verifier reads
text and cannot see a diagram.

**Fix direction:** when the question carries a figure that came from the
reference (`reference_item_id` set and `figure_action` is `keep`), forbid
changing any value the figure shows — or force `figure_action: "change"` so the
image is edited to match.

## High

### H0 — Redrawing a figure strips colour, destroying colour-coded diagrams

**Where:** `src/lib/ai/images.ts` — `STYLE_SUFFIX`, applied to
`redrawFigureFromSource()`
**Verified live** on paper `a5954a03`, Q6 (source Q15).

`STYLE_SUFFIX` opens with "Black and white line diagram only: no shading, **no
color**". That is right for a circuit and wrong for the one topic where colour
*is* the physics.

Q6 asks for the resistance and tolerance of a carbon resistor with bands
"Yellow, Violet, Brown, and Gold". The redrawn figure shows **four identical
black bands**. The information the diagram existed to carry is gone; the
student can only answer from the words in the stem, and a student who reads the
figure gets nothing. The original crop was better — it at least printed the
colour names under the bands.

Resistor colour codes are the obvious case, but any figure whose meaning is
carried by colour has the same problem.

**Fix direction:** either exempt colour-bearing figures from the monochrome
rule (detect "colour"/"color"/a colour-name list in the question text or the
extractor's `figure_description` and drop that clause), or refuse to redraw
them and keep the crop, which is always faithful.

### H1 — The landing page advertises a Word export that does not exist

**Where:** `src/app/page.tsx:39` and `:49`

> "Print-ready PDF with your institution's letterhead, and **clean editable
> Word files** — question paper and answer key as separate documents."

> "…render proper mathematical notation everywhere: on screen, in PDF, and as
> **native equations in Word**."

Commit `fdbea5f` ("Switch to Gemini, simplify exports to PDF…") deleted
`src/lib/docx/build.ts`, `image.ts` and `math.ts`, and its own message says it
removed "the docx builder, print routes and the docx/temml" dependencies.
`temml`, `mathml2omml` and `docx` are absent from `package.json`. There is no
DOCX route.

A teacher choosing this product for Word export finds none.

### H2 — The PDF failure message points at two features that were removed

**Where:** `src/app/api/papers/[id]/export-pdf/route.ts:64`

> "Building the PDF failed (…). You can still use the **Print view** or the
> **Word export**."

Both were deleted in `fdbea5f`. When PDF rendering fails — the one moment the
teacher most needs a way out — the app offers two that do not exist.

### H3 — AGENTS.md documents a DOCX pipeline that is gone

**Where:** `AGENTS.md`, math-rendering bullet

> "LaTeX→MathML(temml)→OMML(mathml2omml) for DOCX (`src/lib/docx/math.ts`)"

That path does not exist. This is the file every future contributor (human or
AI) reads first, so a stale entry here propagates into work built on it.

### H4 — All figure crops are posted in one request, with no size ceiling that matches the platform

**Where:** `src/lib/schemas.ts` — `referenceCropsSchema`;
`src/components/new-paper/NewPaperWizard.tsx` — `sendFigureCrops()`

The schema allows up to `MAX_REFERENCE_ITEMS` (250) crops at up to 1 MB each —
250 MB — and the wizard sends every crop in a single POST. Vercel's serverless
request body limit is about 4.5 MB.

A ten-page bank with ~15 figures is roughly 1 MB and fine, which is why this
has not bitten yet. A figure-dense bank (a chapter of circuit questions) can
exceed the limit, and the failure is quiet: `sendFigureCrops` swallows it
deliberately, so every figure silently falls back to a redraw or to nothing.

**Fix direction:** send crops in batches of ~8, and lower the per-crop cap.

### H5 — Reference page upload sits close to the same limit

**Where:** `src/lib/schemas.ts` — `referencePagesSchema`

10 pages × 2,000,000 chars allowed = ~20 MB against the same ~4.5 MB limit.
Real payloads are ~150–250 KB per page (~2 MB total), so this is a latent
rather than active failure — but a higher-resolution render or a larger page
count would cross it, and the whole extraction fails at once.

## Medium

### M0 — Regenerating a question silently discards every other unsaved edit

**Where:** `src/components/review/PaperReview.tsx`, the `onReplaced` handler

```ts
onReplaced={(next, originalId) => {
  setQuestions((prev) => prev.map((x) => (x.id === originalId ? next : x)));
  setDirty(false);
}}
```

Edits on the review screen live in component state until "Save changes" is
pressed — `mutate()` sets `dirty` true. A regenerate (or an AI edit, which uses
the same handler) then clears `dirty` **unconditionally**, because the
regenerate route saved *its own* replacement server-side.

So: fix the wording of question 5, then regenerate question 12. The banner
flips to "All changes saved", the beforeunload guard stops arming, and the edit
to question 5 exists only in the tab. Closing it loses the work, with the UI
having explicitly said it was saved.

**Fix direction:** the route already persists the whole `questions` array, so
either have `onReplaced` leave `dirty` alone, or send the current in-memory
questions with the regenerate request so the save is genuinely complete.

### M1 — "Reuse last paper's setup" can strand the wizard in reference mode

**Where:** `src/components/new-paper/NewPaperWizard.tsx` — `applyLastPaper()`,
and the `refPages.length > 0` gate on the "How to use it" control

`/new` loads the previous paper's `settings`. If that paper was reference-led,
the copy carries `source_mode: "reference"` but there is no PDF and no bank.
Step 1 then shows everything disabled with "switch it off on the last step" —
but the control that switches it off only renders **once a PDF is uploaded**.

The teacher is told to use a control they cannot see. Generation is blocked by
the guard in `generate()`, so nothing corrupt is produced; they are simply
stuck until they upload a PDF or reload.

### M2 — The user cap counts papers, the global cap counts batches

**Where:** `supabase/migrations/001_init.sql` — `consume_generation()`

`consume_generation` is called once per paper and increments
`generations_today` by 1 — so a user's cap of 10 means ten papers. The global
check in the same function counts rows:

```sql
select count(*) from public.usage_logs
where action = 'generate_batch' and created_at >= current_date;
```

That counts **batches**, and a 45-question paper logs about eight. So
`global_daily_cap: 500` is roughly 62 papers, not 500. The two limits are in
different units, and the admin panel's number means something other than it
appears to.

### M3 — The "generate the remaining N" banner cannot be dismissed

**Where:** `src/components/review/PaperReview.tsx` —
`remaining = paper.settings.question_count - questions.length`

A teacher who deliberately deletes five weak questions to shorten a paper is
told, permanently, that generation "stopped early" and offered a button to add
them back. There is no way to say "this paper is the length I want".

### M4 — There is no test suite

No framework, no test files, no `test` script. Every check in this codebase is
manual. For an app whose stated first priority is correctness, the highest-value
targets are pure and easy to cover: `selectReferenceItems` / `orderByVariety`
(variety guarantees), `trimBoxToFigure` / `toTextLines` (crop trimming),
`resolveCorrectIndex`, `stripSectionPrefix`, `sectionSlotMarks`,
`unfilledSlots`, and `blueprintSchema` round-tripping.

## Confirmed working

Checked live on paper `a5954a03` while auditing, and worth recording so nobody
"fixes" them later:

- **Redraw quality.** The redrawn two-circuit figure for source Q37 is correct
  — both circuits, right topology, 10 Ω / 10 V / V₁ / A₁ / i₁ all present — and
  the leaked question text and stray "(a) V > V…" options that polluted the raw
  crop are gone. Image-to-image redraw does what it was built to do.
- **Redraw budget degradation.** 15 figure questions: 10 carry redrawn images
  (UUID filenames), 5 kept their original `ref-*.jpg` crops after the
  `MAX_FIGURE_QUESTIONS` ceiling was reached. Exactly the intended behaviour —
  a redraw never loses a figure.
- **Variety.** All 45 questions carry distinct "From PDF Qn" provenance.
- **Topic grouping** now renders on the review screen as well as the export.

## Not yet verified

1. **Whether C1 reproduces end-to-end.** The code path is conclusive
   (`unfilledSlots` returns `plan.slice(existing.length)` whenever no slot has
   a `section_id`, which is every reference paper), so this was not reproduced
   live — doing so means deleting a question from a real paper and spending
   generation quota to prove what the code already states.
2. **Whether the figure-contradiction fix (this session) holds** in a fresh
   variant-mode run: every figure question should now reproduce its source's
   values exactly. The papers on the dashboard all predate that deploy.
3. **Whether C3's fix works.** Regenerating Q12 of paper `a5954a03` after the
   deploy exercised the new prompt and came back with **no verifier note at
   all** — but the replacement source (Q39) has no figure, so the run tested
   `has_figure: false`, not the branch that was broken. It did confirm the
   replacement picker avoids used sources: Q45 became Q39, not a duplicate.
   A clean test needs a regenerate that lands on a figure-bearing source, or a
   fresh reference paper; the honest check is whether figure questions still
   carry the "entirely absent from the text" wording.
