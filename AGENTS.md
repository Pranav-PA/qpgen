# QPGen project notes

- AI Question Paper Generator for teachers (JEE/NEET/Board). See README.md for setup.
- Correctness is priority #1: generated questions go through a second-pass AI verifier; anything unconfirmed gets `needs_review` flags shown to the teacher. Never remove the "review before distributing" notices.
- Question paper and answer key must always export as separate documents.
- Question/solution text stores inline LaTeX (`$...$`). Rendering: KaTeX in UI/print (`src/components/MathText.tsx`), LaTeX→MathML(temml)→OMML(mathml2omml) for DOCX (`src/lib/docx/math.ts`).
- Generation is client-driven in batches (`/api/papers/[id]/generate-batch`), resumable; slot plan is deterministic (`src/lib/ai/plan.ts`).
- Rate limiting is atomic SQL (`consume_generation` in `supabase/migrations/001_init.sql`); RLS is the security boundary — service-role client (`src/lib/supabase/admin.ts`) only for rate-limit bookkeeping, usage logs, and admin routes.
- `MOCK_AI=true` runs generation with free mock questions for local dev.
- Model IDs/pricing are env-overridable in `src/lib/constants.ts`; verify current OpenAI models before changing defaults.
- Questions may carry a `figure`: SVG drawn by the model for circuits, ray diagrams and graphs. It is allowlisted in `src/lib/svg-sanitize.ts` **on arrival** and only the cleaned markup is stored, so renderers never re-check. Never route unsanitised SVG to `QuestionFigure` or `lib/pdf/html.ts`. A figure always forces `needs_review` — the verifier reads text and cannot tell whether a drawn circuit is correct.
- The PDF renderer makes **no network requests** (`src/lib/pdf/render.ts` loads an in-memory string). Anything referenced by URL silently vanishes from the export; images must go through `fetchImageAsDataUri` in `src/lib/pdf/assets.ts`. SVG needs no such step.
- Diagrams are admin-controlled via the `images` key in `app_config` (`getImageConfig` in `src/lib/api.ts`); the new-paper screen tells teachers when they are off or degraded. Raster image generation is deliberately **not** built: tested July 2026, SVG handles physics well, but biology degrades to labelled boxes and generated raster would place labels on anatomy it may have drawn wrong.
- `settings.figure_mode` picks the diagram control. `"fixed"` (default, and what every pre-existing paper does) honours `figure_questions` exactly by pre-marking slots in `plan.ts`. `"auto"` — used for board-syllabus papers — marks no slots and lets the model write `figure_spec` wherever a question needs one. Cost is bounded either way: `generate-batch` counts the paper's existing figures and stops honouring specs past `MAX_FIGURE_QUESTIONS`, flagging any question that lost its diagram to the cap. Never make `"auto"` unbounded — each image is a real per-image bill.
- Board curriculum data lives in `src/lib/curriculum/` (KSEEB classes 8–10, Science/Maths/Social Science). Chapter titles come from the **official KTBS textbooks**, not tutoring sites — those still serve the pre-2014 Karnataka books alongside the current ones and disagree with each other. KSEEB is not current NCERT: it keeps chapters NCERT deleted in 2023 and reorders Class 10 Maths, so `curriculumRules()` in `lib/ai/prompts.ts` names retained chapters to the model explicitly. Never "correct" the data towards NCERT.
- **Being in the textbook and being examinable are different things.** Class 10 Science omits Periodic Classification of Elements, Sources of Energy and Sustainable Management of Natural Resources from SSLC assessment (2024-25 question paper format; all three 2025-26 model papers avoid them). They stay listed with `excluded` set — off by default, out of the blueprint grid, and named to the model as out of scope — so a teacher can still add one back for a school test. `examinableChapters()`, not `subject.chapters`, is what defaults and seeding use.
- SSLC Science allocates marks by **theme**, not per chapter — a deliberate 2019-20 change so teachers stop drilling high-scoring chapters. The five themes total 80 and reconcile exactly with the model papers' parts (Materials 25 → Chemistry; Natural Phenomena 13 + How Things Work 14 → Physics 27; Living World 25 + Natural Resources 3 → Biology 28). Do not reintroduce per-chapter weightage for this subject: aggregator sites publish one, it is not official, and it does not reconcile.
- The board publishes a **closed list of diagrams a student may be asked to draw** (`drawable_figures`, ~15% of marks). A "draw and label" question must ask for one of those and nothing else. Diagram-*based* questions, where the student is shown a figure, are unrestricted — different thing.
- Anything that builds a `Blueprint` in code (presets, the extractor) must round-trip through `blueprintSchema`/`createPaperSchema` before you trust it — the API validates on save, so a preset that only "looks right" in a unit check still fails at paper creation. A run's `label` is its printed instruction on a Karnataka paper ("Four alternatives are given…", ~160 chars), which is why it is bounded at 300 like a section instruction rather than as a short label.
- A blueprint part (`BlueprintSection`) can split into runs (`BlueprintSubGroup`) that carry **their own** `marks_per_question`. Karnataka's SSLC Science paper needs it — PART-A prints 1-, 2-, 3- and 4-mark runs under one heading. Read per-slot values through `sectionSlotMarks`/`sectionSlotTypes`, never `section.marks_per_question` directly. The SSLC preset in `src/lib/curriculum/presets.ts` is transcribed from KSEAB's three 2025-26 model papers (83-E); the structure is identical across all three, which is what makes it safe to hardcode.
- Not yet representable, and known gaps against the real SSLC paper: per-question **"OR" alternatives** (the app only has "answer any N of M"), **answer-side diagrams** ("draw and label a nephron" — the figure belongs in the answer key, not the question), and **tables inside question text**. The blueprint-upload extractor also reads only one mark value per part, so an uploaded SSLC blueprint loses its runs — use the preset for those.
